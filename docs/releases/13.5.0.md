# 13.5.0 — Canonical release-note categories

## Added

- Adds canonical `Added`, `Changed`, and `Fixed` categories for new PR/MR release-note authoring alongside `Internal changes`, with each entry classified by its intent.

## Changed

- Preserves the explicit source category when synthesizing existing release notes and instructs consumers to continue accepting the legacy `New features`, `Improvements`, and `Fixes` aliases during rollout.
- Keeps the compatibility rollout consumer-before-producer: consumers must support the canonical headings before producers switch their default, while existing legacy content remains readable.

## Internal changes

- Requires manual review when an existing source category conflicts with the canonical classification or remains genuinely ambiguous; `Internal changes` stays excluded from public consumers.
