# 12.2.0

Version 12.2.0 is a compatible instruction-only minor release.

## Changes

- Replaces the universal local repository-wide gate rule with candidate-bound, risk-based validation and exactly one broad final gate for every tracked implementation.
- Allows qualifying exact-candidate CI to substitute for local broad validation only with matching source/test SHAs, known equivalent-or-broader coverage, present required jobs, passed targeted and risk-specific checks, and a successful terminal result.
- Makes CI-gated candidate publication a separately authorized `merge-request` pre-gate transition, preserving Draft-by-default readiness and keeping merge, release, and deployment authority separate; without that authority, local broad validation remains mandatory.
- Requires provider delivery to report source head and actual tested SHA separately, including authoritative GitHub check/workflow and PR test-merge OIDs where applicable, and to fail closed when current source-to-tested mapping is unavailable.
- Defines simple, medium, and high risk proportionally using blast radius, shared/public contracts, data/security/migrations, reversibility, test-selection confidence, and environment parity.
- Separates existing automated browser/E2E tests from agent-driven interactive browser smoke, with explicit-request/acceptance-only triggers, adapter-owned preflight, semantic and visual evidence, and bounded failure handling.
- Makes candidate identity, source-head versus tested-SHA reporting, evidence invalidation after later mutations, and fresh candidate-bound evidence reuse explicit across implementation and provider delivery.
- Requires an authoritative native Plan write and inspection with exactly one active phase, followed by matching native Goal inspection or creation, before Codex dispatches any tracked writer; prose status is not gate evidence.

No runtime migration, orchestration database, or global helper installation is required.
