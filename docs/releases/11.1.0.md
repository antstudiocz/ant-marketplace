# (ant) 11.1.0

## Proportional quality and reliable tests

- During read-only discovery, before continuity/planning, derive only material quality attributes and constraints from repository and user evidence; record lighter/heavier tradeoffs in the Plan and writer/reviewer assignments, then choose the smallest durable solution.
- Require deterministic async and concurrency-sensitive tests: observable synchronization, bounded timeouts, isolated state, cleanup, virtual time where possible, and relevant CI-like repeat/shuffle/seed coverage. Retries remain diagnostic only; sleeps, weakened assertions, skipped coverage, and hidden failures are not acceptable flake fixes.
- Keep performance and scalability claims evidence-based. Heavy performance or fault scenarios can be assigned to benchmark, nightly, or manual validation while merge-request checks protect the smallest representative invariant.

## Runtime smoke and adjacent findings

- Executable, runtime, and user-visible changes now plan their smallest realistic smoke flows before implementation. After the final suite, the orchestrator discovers actual host/repository capabilities, offers every applicable testing surface with exactly one evidence-based recommendation, and leaves tool selection to the user (honoring an explicit prior choice).
- Smoke reports include the tested environment and head, exact flows, expected versus observed outcomes, side effects, gaps, and screenshots where supported. Smoke supplements automated validation; required failed/unavailable/declined smoke affects readiness, while optional declined smoke is reported unverified without an invented blocker.
- All verified, material, actionable adjacent findings are reported separately from the execution retrospective, without an arbitrary count cap. Current correctness, requirement, or verification gaps are fixed or lower/block readiness. Repeated violations may be recommended for repository lint/ratchet/enforcement, but no CI enforcement or scope expansion is automatic.

## Contract readability

- The orchestrator contract (`SKILL.md`, `references/lifecycle.md`, both host adapters) is rewritten from long qualified prose into imperative checklists, decision procedures, and tables. Semantics are unchanged: the same rules, gates, roles, routes, and the four readiness verdicts remain, and the readiness classification keeps its original first-match order.
- The `merge-request` skill receives the same readability pass: intent classification, choice resolution, the final snapshot rule, and per-provider pipeline observation are now explicit numbered procedures, with unchanged rules, templates, and CLI commands.

## Use and migration

No runtime migration is required. Update the plugin to 11.1.0, restart Codex or reload Claude Code, and use the existing `implementation-orchestrator` entry point. Existing plans gain the quality, deterministic-test, adjacent-finding, and runtime-smoke gates when the relevant task attributes apply; instruction-only or non-runtime work remains proportional and does not receive an artificial smoke step.
