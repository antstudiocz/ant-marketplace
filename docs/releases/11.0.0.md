# 11.0.0

Version 11.0.0 is a breaking redesign of the implementation orchestrator.

## What changed

- The workflow is instruction-only and host-neutral in its shared semantic core. It uses the host's native Plan and Goal; it does not rely on `/goal`, `/plan`, pseudo-state, custom ledgers, runtimes, or compatibility paths.
- The native Plan records phases or waves with one top-level `in_progress` item. Actual concurrent work is represented by native agent/thread state. Stable in-scope follow-ups amend the active Plan and Goal; material scope or contract changes require a delta decision and authorization.
- Disjoint backend, frontend, test, research, and implementation workers may run in parallel behind one integration lead when contracts are stable. Related agents keep operational repair context local and send root compact knowledge deltas. Every implementation still receives independent Strong-at-High final review.
- Codex routing is explicit: root and Strong roles use `gpt-5.6-sol` at High; all other Codex children use `gpt-5.6-luna` at proportional High, Medium, or Low effort. Terra routing and fallback are removed. Capability tier and reasoning effort remain separate controls.

## Migration and use

1. Update the plugin to 11.0.0 and start a fresh host session.
2. Select or verify the Codex root as Sol High, or the Claude root as `best` + `max`.
3. Invoke the orchestrator and let it perform read-only discovery and present the proportional native Plan.
4. For authorized implementation, establish or reuse the native Goal only after the Plan is stable and before tracked-writer dispatch. Do not run legacy `/goal` or `/plan` commands.
5. Use the native agent/thread state for parallel workers; keep shared contracts and files with one integration lead, then complete independent review, final validation, retrospective, and any separately authorized delivery.
