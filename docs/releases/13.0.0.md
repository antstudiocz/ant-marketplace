# 13.0.0 — Durable orchestration planning

## Breaking changes

- Replaced the mandatory host-native Plan/update_plan gate with a root-owned, host-independent Git-tracked planning bundle under `docs/implementation-plans/YYYY/MM/<slug>/`.
- Codex still requires a matching native Goal for safety. Goal closure remains terminal-only; durable plan checkpoints carry phase progress. Claude native Goal and Plan UI support are optional.
- Clarified root-only planning-doc writes, child read-only access, recursive routing capsules, compaction recovery, candidate freeze, and candidate-bound evidence invalidation.

## Documentation and maintenance

- Added the bootstrap plan for this redesign and aligned the orchestrator skill, host adapters, intake guidance, and user documentation.
- Preserved exactly three public skills: `implementation-orchestrator`, `merge-request`, and `brand-design`.
- No runtime, hooks, machine state, compatibility shim, public skill, alias, product code, or delivery behavior was added.
