# Codex Routing Adapter

For implementation-authorized or later-approved work whose objective and plan are stable, establish the native goal before tracked-writer dispatch when `get_goal`, `create_goal`, and `update_goal` are exposed. Inspect the current goal with `get_goal` first. Reuse a semantically matching active goal; if none is active, create one with an objective that states the verifiable outcome, acceptance conditions, material constraints, required checks, and only delivery already authorized. Omit `token_budget` unless the user explicitly requested one.

Never overwrite, complete, or block an unrelated active goal. If the active goal conflicts with the verified plan, pause tracked execution and ask the user to resolve it. If the native goal tools are unavailable, state that limitation and continue with the native plan without fabricating goal state. Use `update_goal` with `complete` only after the goal's scoped implementation, required review, final validation, retrospective, and included delivery are actually complete. Use `blocked` only when Codex's native repeated-blocker rule is met, never for ordinary approvals or clarifications.

Select or verify the already-running root at task/session level before orchestration begins. Root uses the strongest available route: with the current catalog, `gpt-5.6-sol` at `Max`. Native spawn selectors control children only; they cannot change an already-running root. Treat these identifiers as current routing examples, not the shared workflow contract. If root control is not exposed, use the strongest available root setting and report that it is not verified as maximum.

Use the active spawn surface's explicit native model and reasoning-effort selectors to pin every child and nested child; never let one inherit root `Max`. Supply a concise, self-contained assignment with every task-relevant fact instead of relying on conversation history.

Use `fork_turns="none"` for read-only scouts, reviewers, validation helpers, slice workers, and every nested dispatch. For the one primary tracked implementation owner, use `fork_turns="1"` only when the immediately preceding user turn explicitly authorizes execution of the stable plan. That single turn carries authorization provenance for host safety; the assignment still carries the complete task contract. Never omit `fork_turns`, use `all`, or use a value above `1`. Keep safety-sensitive tracked work with that owner instead of redispatching it to history-free slices. If the preceding user turn is not authorizing, use `none` and do not manufacture or infer provenance.

Route Strong work to `gpt-5.6-sol` at `High`. Route Balanced work to `gpt-5.6-terra` at the role's `High`, `Medium`, or `Low` effort. Route Fast work to `gpt-5.6-luna` at `Low` or `Medium` only when the active spawn surface exposes Luna; otherwise use `gpt-5.6-terra` at that same effort. This Luna-to-Terra route is the only fallback. Cap every child at `High`. Positive bounded history still requires explicit model and effort selectors. If Sol, Terra, the requested effort, or the required `fork_turns` mode cannot be enforced, do not dispatch and report the limitation.
